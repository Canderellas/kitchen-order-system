1\. Какая команда вызывала наибольшие сложности до начала практики?

До практики больше всего вопросов возникало к командам git merge и git revert. Было не до конца понятно, по какому принципу Git анализирует различия между ветками, как именно он решает, какие изменения оставить, и каким образом происходит объединение истории. К тому же определённую трудность представлял неожиданный запуск редактора Vim и выход из него.

2\. Почему так важно указывать user.name и user.email перед созданием коммитов?

Эти данные необходимы для идентификации автора изменений. Git привязывает каждое изменение к конкретному разработчику, и эта информация навсегда сохраняется в истории проекта .Если не заполнить эти параметры: становится невозможно точно определить, кто внёс те или иные правки; GitHub не может связать коммиты с профилем пользователя, из-за чего активность отображается некорректно; в рабочих проектах такие «анонимные» коммиты затрудняют аудит и контроль безопасности.

3\. В каких ситуациях git revert безопаснее, чем git reset?

git reset лучше не использовать, если ветка уже доступна другим участникам, так как он переписывает историю и может привести к конфликтам при синхронизации. git revert в этом смысле гораздо безопаснее: он не удаляет прошлые коммиты, а создаёт новый, который отменяет их изменения. История остаётся неизменной, а коллеги могут спокойно продолжать работу без риска потерять свои наработки.

4\. Как .gitignore помогает предотвратить утечку данных?

С помощью .gitignore можно исключить из индексации файлы, содержащие чувствительную информацию, — например, .env, конфиги с паролями, токенами или ключами API. Если такие файлы случайно попали бы в публичный репозиторий, их почти сразу обнаружили бы автоматические сканеры, что привело бы к серьёзным последствиям. Правильно настроенный .gitignore защищает проект от подобных инцидентов.
